# 个人项目简历素材

首次整理日期为 2026-11-09，最近修订日期为 2026-11-10（北京时间）。用户将本项目定位为简历中的补充项目，对岗位方向没有偏好。本稿依据用户提供的投递管理表述，整合投递流程、面经整理与招聘邮件同步，供用户核对使用。

## 简历可用版本

### 个人求职管理与面经整理平台｜个人项目

**技术栈**　Vue 3、TypeScript、Pinia、FastAPI、SQLAlchemy、SQLite、Monaco Editor

**项目背景**　面向个人求职场景，构建集投递跟踪、面经采集与招聘邮件扫描于一体的管理平台，支持求职信息集中管理与进度同步。

**核心实现**

- **投递流程管理**　实现全流程的求职进度跟踪，按“公司—岗位—轮次”组织投递流程，支持岗位独立推进、轮次安排与结果复盘。通过统一日程视图汇总测评、笔试与面试安排，按开始时间排序，并分类展示待办、已办及过期事项。
- **面经采集与题库沉淀**　通过统一接口接入小红书 CLI，串联正文与图片采集、本地 OCR、人工校对和 LLM 题目抽取，基于平台与内容标识去重，校验抽取结果的原文引用并保留来源，支持确认后导入题库。
- **招聘邮件自动同步**　采用“事件提取—候选检索—公司对齐”的两阶段 LLM 流程，首轮从邮件生成事件和关键词，后端逐词限量检索并去重，将次轮候选限制在 100 家公司以内。结合 IMAP 增量扫描、原文校验和事件去重，将明确的招聘进展同步为岗位状态与轮次更新。

## 每条技术点对应什么问题

### 投递流程与数据一致性

业务上，同一家公司可能先投岗位 A，再改投 B，之后重新投 A。只修改当前岗位名称会混淆历史。项目为流程保存代次，在阶段、轮次和结果中保存当时的岗位名称，并结合明确关联定位归属。写入时检查目标版本和已有状态，相关变更在数据库事务中提交。

可准备的追问包括为什么名称不足以标识一次投递，岗位代次与岗位快照各自解决什么问题，以及旧记录缺少快照时如何处理。

实现依据见 [岗位归属解析](../backend/app/modules/jobs/positions.py)、[岗位业务服务](../backend/app/modules/jobs/service.py)、[岗位数据迁移](../backend/app/core/database.py)和 [岗位历史说明](job-position-history.md)。

### 面经采集与资料整理

浏览器 MCP 与 CLI 的搜索、登录和内容读取方式不同。统一采集契约将两者转换成相同的材料结构，上层的 OCR、校对、AI 整理与题库导入可以复用。搜索结果保留原采集方式，切换默认方式后仍按结果原来的方式读取材料。数据库通过平台和内容标识的联合唯一约束，处理同一内容经两种方式重复采集的情况。

AI 返回 JSON 后，服务端检查结构、来源分段与引文是否真实存在于材料中。用户可以校对 OCR 文字并确认题目后再保存。资料被修改后旧整理报告失效，材料版本检查用于拒绝覆盖较新的内容。

可准备的追问包括适配接口解决了什么重复工作，为什么模型已经输出 JSON 还需要校验，以及原文引用存在能验证到哪一层。

实现依据见 [采集契约](../backend/app/modules/experiences/sources/contracts.py)、[来源注册](../backend/app/modules/experiences/sources/registry.py)、[统一采集服务](../backend/app/modules/experiences/sources/service.py)、[本地 OCR](../backend/app/modules/experiences/ocr.py)和 [面经整理服务](../backend/app/modules/experiences/service.py)。

### 招聘邮件自动同步

用户发现公司全称与数据库简称不一致会影响关联，进一步提出公司数量增长后的上下文规模问题，并明确选择固定两轮独立请求。第一轮从邮件提取招聘事件与关键词，后端逐关键词查询并合并候选，第二轮完成候选公司对应，再按具体岗位及代次校验和写入。检索默认最多 5 个关键词、每词 20 个公司，控制模型候选输入上限为 100 家。

IMAP 游标记录收件增量，模型处理状态与收件进度分开保存，事件键与已有轮次比对处理重复邀请，原文引用和时间规则检查提取依据，事务将岗位变化与邮件更新记录一起提交。歧义事件可由用户核对具体岗位。关键词检索和固定两轮的方向由用户提出，代码与回归测试由 AI 辅助完成。

真实 163 连接及一次新增邮件为 0 的扫描已验证。另以虚构邮件和 603 家示例公司调用当前模型两次，检索并集为 2 家并选中邮储公司；该样例的规模与结果作为面试验证材料。真实招聘邮件的识别准确率、关键词覆盖率和业务节省时间待积累样本测量。

实现依据见 [两轮模型请求](../backend/app/modules/mailbox/analysis.py)、[候选检索与事件执行](../backend/app/modules/mailbox/execution.py)、[收件及处理状态](../backend/app/modules/mailbox/service.py)和 [邮箱回归](../backend/tests/test_mailbox.py)。

### 编辑器与状态恢复

代码练习需要频繁修改题目、代码和思路。Monaco 提供高亮及内置补全，自动保存控制器在停止输入 1 秒后提交快照。同一时间只执行一次保存，慢请求期间产生的新修改会在后续串行保存。离开页面时等待最新修改写入，失败时保留当前输入并按操作类型提供重试。

列表通过 URL 保存明确的查询条件，通过 Pinia 管理应用内记忆，并以 sessionStorage 保留同一标签页的会话记忆。搜索、分页和位置按页面、分类及查询条件分别保存。数据加载完成后校正页码并恢复实际滚动容器，缓存损坏或浏览器拒绝存储时回退到内存记忆。

可准备的追问包括防抖为什么仍需要配合串行保存，旧请求返回时如何处理用户的新输入，以及 URL、Pinia 与 sessionStorage 分别保存什么。

实现依据见 [自动保存控制器](../frontend/src/modules/coding/autosave.ts)、[代码练习页面](../frontend/src/modules/coding/views/CodingDetail.vue)、[视图序列化与会话存储](../frontend/src/shared/state/pageState.ts)、[列表恢复逻辑](../frontend/src/shared/composables/useListViewState.ts)、[编辑器验证](validation-coding-editor-2026-10-25.md)和 [列表状态验证](validation-page-state-2026-10-25.md)。

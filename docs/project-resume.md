# 个人项目简历素材

整理日期为 2026-11-09（北京时间）。用户将本项目定位为简历中的补充项目，对岗位方向没有偏好。本稿按已实现功能整理为全栈 AI 应用经历。

## 简历可用版本

### 个人求职管理与 AI 面试助手｜个人项目

**技术栈**　Vue 3、TypeScript、FastAPI、SQLAlchemy、SQLite

面向个人求职场景，整合投递跟踪、面经收集、模拟面试与复习管理，支持业务记录本地持久化。

- **模块化架构与数据建模**　采用前后端分离架构，通过模块注册统一组织路由与菜单。以岗位代次、名称快照及关联记录管理同一公司的多次投递，隔离各岗位的阶段、轮次和结果历史。
- **AI 面试与异常恢复**　实现简历驱动的多轮追问和结构化复盘，持久化简历快照与对话。通过请求去重、状态条件更新及执行标识隔离，支持失败重试与刷新恢复，防止重复保存和迟到回复覆盖新结果。
- **面经采集与知识整理**　以统一适配接口接入小红书 MCP / CLI 采集，结合本地 OCR 和大模型提取面试问题。使用 Pydantic 结构校验、原文引用校验与人工确认，将资料转为可追溯的复习题目。

## 每条技术点对应什么问题

### 模块化架构与数据建模

投递、问答、代码练习、面经与 AI 面试分别维护自己的接口和页面。前端模块注册表提供路由与菜单配置，后端扫描模块声明后挂载接口，新增功能可以沿用已有接入方式。

业务上，同一家公司可能先投岗位 A，再改投 B，之后重新投 A。只修改当前岗位名称会混淆历史。项目为流程保存代次，在阶段、轮次和结果中保存当时的岗位名称，并结合明确关联定位归属。写入时检查目标版本和已有状态，相关变更在数据库事务中提交。

可准备的追问包括为什么名称不足以标识一次投递，岗位代次与岗位快照各自解决什么问题，以及旧记录缺少快照时如何处理。

实现依据见 [后端模块注册](../backend/app/core/module_registry.py)、[前端模块注册](../frontend/src/modules/index.ts)、[岗位归属解析](../backend/app/modules/jobs/positions.py)、[岗位业务服务](../backend/app/modules/jobs/service.py)和 [岗位历史说明](job-position-history.md)。

### AI 面试与异常恢复

模型调用耗时较长，可能超时，也可能在用户重试后才返回旧结果。面试流程先保存回答与逻辑请求，再调用模型。相同请求标识复用已有操作，条件更新用于限制同一场面试同时执行的生成请求，每次重试使用新的执行标识，写回时核对该标识与请求状态。

简历快照固定本场材料，原简历修改后仍可复盘当时的面试。结构化复盘会检查问答消息对应关系和简历引文，复盘条目可以经确认转入问答或待办，目标记录与导入记录在同一事务中保存，并通过唯一约束处理重复确认。

可准备的追问包括请求标识与执行标识为什么需要分开，模型超时时回答保存在哪，以及刷新后从哪里恢复对话。

实现依据见 [面试服务](../backend/app/modules/aitools/interviews.py)、[面试数据模型](../backend/app/modules/aitools/models.py)、[面试回归用例](../backend/tests/test_resume_interview.py)和 [功能契约](resume-interview.md)。

### 面经采集与知识整理

浏览器 MCP 与 CLI 的搜索、登录和内容读取方式不同。统一采集契约将两者转换成相同的材料结构，上层的 OCR、校对、AI 整理与题库导入可以复用。搜索结果保留原采集方式，切换默认方式后仍按结果原来的方式读取材料。

AI 返回 JSON 后，服务端检查结构、来源分段与引文是否真实存在于材料中。用户可以校对 OCR 文字并确认题目后再保存。资料被修改后旧整理报告失效，材料版本检查用于拒绝覆盖较新的内容。

可准备的追问包括适配接口解决了什么重复工作，为什么模型已经输出 JSON 还需要校验，以及原文引用存在能验证到哪一层。

实现依据见 [采集契约](../backend/app/modules/experiences/sources/contracts.py)、[来源注册](../backend/app/modules/experiences/sources/registry.py)、[统一采集服务](../backend/app/modules/experiences/sources/service.py)、[本地 OCR](../backend/app/modules/experiences/ocr.py)和 [面经整理服务](../backend/app/modules/experiences/service.py)。

## 其他可按岗位替换的技术点

- 前端交互方向可以展开列表状态恢复。项目按页面、分类和查询条件保存筛选、分页及滚动位置，并通过会话存储恢复。实现依据见 [列表状态](../frontend/src/shared/state/pageState.ts)和 [列表状态说明](page-state.md)。

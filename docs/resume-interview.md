# 简历面试与复盘

## 使用流程

保存简历 → 开始面试 → 根据经历作答与追问 → 生成复盘 → 确认加入问答或待办。

提问材料由本场简历快照、可选目标岗位、考察重点和已保存的对话组成。题库仍负责知识积累与复习，不再作为面试的必选题单。

简历支持粘贴，以及 PDF、DOCX、TXT、Markdown 导入。导入接口只返回待核对文本；用户保存后才写入简历表。上传文件在处理结束后关闭，项目仅保存核对后的文字，不通过模型提取。文件最多 5 MB，PDF 最多 20 页，文本最多 30000 字；扫描图片和加密 PDF 会返回明确提示。

更新或删除原始简历后，已经开始的面试保留原快照。已提交的回答会先入库；模型超时或页面关闭不会丢失已经保存的内容。未提交的输入仍属于当前页面草稿。

## 状态与错误恢复

- 面试状态为 `active` / `completed`，生成复盘成功后才进入完成状态。
- 每次逻辑请求携带 UUID；消息历史由后端读取。相同标识的成功请求返回已保存结果，相同标识不能对应另一份回答。
- 逻辑请求分为开场、回答后追问、复盘，记录 `pending` / `failed` / `succeeded`。
- 同一场面试最多执行一个生成请求。刷新时读取已保存的状态，页面只在生成期间轮询。
- 后端模型调用上限 120 秒；150 秒后仍未完成的执行允许恢复。每次重试使用独立的内部执行标识，迟到的旧结果无法覆盖新结果。
- 一次回答最多 6000 字；一场最多 30 次作答，记录过长时提示先生成复盘再开新场次。模型追问使用最近 20 条消息，持久化记录与复盘仍保留完整对话。

## 可追溯复盘

复盘先经过结构校验，再写入数据库：

- 每个实际完成的问答对应关系必须恰好出现一次。
- 提问与回答的消息标识必须属于本场记录，顺序关系必须正确。
- 非空简历引用必须是本场快照中的连续原文。
- 反馈分为回答较充分、仍可深入、需要加强；不生成伪装成客观测量的录用分数。

这些规则保证格式与引用可追溯，不等同于验证模型的所有语义判断。点评质量仍需要真实模型和人工样例评测。

加入问答或待办前，用户可修改标题和内容、选择分类、填写待办截止时间。目标内容与导入记录在同一事务中保存；重复确认复用原目标。已加入内容被删除后，可以再次保存。删除面试不会级联删除已经生成的问答或待办。

## 数据与接口

本功能归属 `aitools` 模块，新增五张 `ai_` 前缀表，由现有模块注册和 `create_all` 创建。简历、对话、报告等运行内容保存在数据库中，遵循根目录 `.gitignore`，不进入 Git 提交。

接口前缀：`/api/aitools`。

| 接口 | 用途 |
| --- | --- |
| `GET/POST /resumes` | 简历列表与保存 |
| `GET/PUT/DELETE /resumes/{id}` | 查看、编辑、删除简历 |
| `POST /resumes/extract` | 文件提取预览 |
| `GET/POST /interviews` | 面试列表与创建 |
| `GET/DELETE /interviews/{id}` | 恢复或删除面试 |
| `POST /interviews/{id}/start` | 根据简历生成开场问题 |
| `POST /interviews/{id}/messages` | 保存回答并继续追问 |
| `POST /interviews/{id}/review` | 结束并生成复盘 |
| `POST /interviews/{id}/retry` | 重试最近一次失败的生成 |
| `POST /interviews/{id}/actions` | 确认加入问答或待办 |

## 本次验证

在项目专用 conda 环境中执行 `python -m unittest discover -s tests -v`：31 项通过。其中 11 项覆盖简历快照保留、模型上下文、回答失败后的恢复、复盘引用与完整性、重复确认、删除后重新导入、并发请求及迟到回复隔离、文件格式提取与错误提示。

执行 `npm run build`：完整类型检查和生产构建通过。既有依赖包体积提示仍存在。

浏览器使用独立示例库与明确标注的模拟回复，完成以下流程，未使用真实个人简历：

1. 在浏览器中构造内存 Markdown 测试文件，触发文件导入，核对文本后保存简历。
2. 开始面试，开场问题引用简历中的项目；对话关联本场快照。
3. 模拟模型超时，刷新后恢复已保存回答，重试成功后回答数量保持不变。
4. 生成复盘，刷新后恢复报告以及已导入状态。
5. 修改预览标题，确认加入问答和待办；切换对应模块后立即可见。
6. 1920、2560 宽屏及 390 像素手机宽度下，准备页、对话和复盘没有横向溢出；宽屏历史栏到达内容区右侧。

PDF、DOCX 使用内存文件通过后端提取测试。浏览器原生文件选择器受工具的工作区路径限制，浏览器文件导入流程采用内存测试文件验证。

真实模型效果、语音合成和麦克风识别尚未端到端验证。模拟服务和测试库仅在被忽略的 `.runtime/` 目录中，用于功能演示，不修改业务模型配置。

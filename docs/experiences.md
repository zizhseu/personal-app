# 面经搜索、采集与整理

从侧栏「面经资料 → 搜索与收集」进入。第一版覆盖小红书图文笔记的关键词搜索、正文保存、图片文字识别、材料校对、AI 提取问题和确认加入问答。

## 使用步骤

1. 点击「连接小红书 → 安装并启动采集服务」。首次会下载固定版本的采集组件和浏览器，需等待准备完成。
2. 点击「获取登录二维码」，用小红书 App 扫码并在手机确认。登录成功后关闭弹窗即可搜索。无需向应用提供密码或其他应用的 Cookie。
3. 输入公司、岗位、轮次等关键词，可选择排序和时间范围。每次最多勾选 5 条笔记，逐条采集；相同笔记不重复保存。搜索访问参数在本机私有缓存中保留约 30 分钟，过期后需重新搜索。
4. 在「本地资料」打开笔记，点击「识别图片」。每次最多处理 6 张；超过 6 张时继续点击，失败的图片不会阻塞尚未识别的图片。识别在本机完成，不使用视觉模型额度。
5. 对照原图校对文字，点击「保存校对」，然后点击「AI 整理文字」。AI 使用「设置 → 大模型」中现有连接；这一步会将正文和校对文字发送给所配置的模型，遵循对应服务的额度与计费。
6. 查看摘要、提取的问题和原文片段，可点击出处返回对应材料。选择「加入问答」，核对分类与问题后确认。来源片段作为资料备注保存，应用不替这些问题生成标准答案。

也可使用「手动导入」粘贴已获取的正文。手动导入不主动访问来源链接，也不自动获取链接中的图片。相同正文不会重复保存。

## 搜索策略与边界

默认的浏览器方式通过本机运行的 [xiaohongshu-mcp](https://github.com/xpzouying/xiaohongshu-mcp) 完成：在扫码登录的独立浏览器中打开小红书搜索页，读取页面已加载的搜索结果与笔记详情。也可在设置中改选 [xiaohongshu-cli](https://github.com/jackwener/xiaohongshu-cli) 的接口方式，能力差异和分别登录的说明见 [内容来源](content-sources.md)。两种方式均不属于官方开放搜索 API，也没有实现 AI 自动规划关键词或多轮补充检索。

- 当前使用平台自身的排序与筛选，读取一批已加载结果，适配器最多处理 40 张卡片；返回数量不代表全部相关内容。本次实测返回 20 条。
- 仅搜索图文笔记，不做视频转写、全量翻页或评论分析。详情接口限制评论数量，评论不进入本应用的面经材料与模型输入。
- 如平台要求重新登录或验证，需由用户处理后重试；应用不会自动绕过验证。
- 笔记标题和作者来自平台，不代表应用已核实作者经历。AI 校验能确认引文确实出现在材料中，问题改写、摘要含义和 OCR 准确性仍需要人工核对。
- 原笔记链接保留标准地址，打开时仍可能需要小红书登录。图片下载地址也可能过期，失败时可手工补充文字。

## 安装与运行

图片识别为可选依赖。在项目专用 `personal-app` conda 环境中，从项目根目录运行：

```powershell
python -m pip install -r backend/requirements-experiences.txt
```

使用 `rapidocr==3.10.0` 与 ONNX Runtime，本次在 Python 3.13 环境实际运行通过。未安装时仍可搜索、采集和手动导入，图片识别会提示安装依赖。首次初始化 OCR 可能需要下载模型。

Windows 可以在页面启动，也可从项目根目录运行：

```powershell
python scripts/xhs_collector.py start
python scripts/xhs_collector.py status
python scripts/xhs_collector.py stop
```

停止会保留登录文件。停止逻辑核对当前进程的完整可执行路径，不按端口盲目终止其他程序。脚本重复启动会复用已有服务；中断的安装可重新启动。

一键启动固定使用 `xpzouying/xiaohongshu-mcp` **v2.5.5** 的 Windows amd64 发布文件，并在执行前核对 SHA256：

```text
cb55674f90c1649c875be9c4cde3af193b02fc34ffc860c40c8d711e6ca53e27
```

来源：[固定版本发布](https://github.com/xpzouying/xiaohongshu-mcp/releases/tag/v2.5.5)、[发布文件与校验值](https://github.com/xpzouying/xiaohongshu-mcp/releases/expanded_assets/v2.5.5)、[HTTP API](https://github.com/xpzouying/xiaohongshu-mcp/blob/v2.5.5/docs/API.md)。上游浏览器按其固定版本下载并校验上游提供的 SHA256。

本应用将采集子进程的缓存和临时目录设在 `.runtime/xhs/`，使用独立浏览器，不读取系统浏览器资料。本次排查确认用户缓存中的浏览器报 Windows SideBySide 错误，项目内副本可以正常启动；未修改浏览器二进制或安装系统组件。

其他系统可自行安装兼容的采集服务，再在「连接设置」填写地址。连接仅接受显式端口的本机 HTTP IP 地址，例如 `http://127.0.0.1:18060`。自定义服务需自行启动；更换地址不会继承原地址的鉴权令牌。

## 保存与恢复

| 位置 | 内容 |
| --- | --- |
| `backend/data/app.db` | 原始正文、识别文字、校对文字、报告、处理状态和问答导出记录 |
| `backend/data/experience-images/` | 已成功识别的图片副本 |
| `backend/data/experience-collector.private` | 采集地址与鉴权令牌 |
| `backend/data/experience-search.private` | 有效期内搜索结果的私有访问参数 |
| `backend/data/xhs/cookies.json` | 此应用扫码产生的小红书登录记录 |
| `.runtime/xhs/` | 采集组件、独立浏览器缓存、临时文件、启动状态和运行日志 |

以上数据及 `references/` 均不进入 Git。私有配置在 Windows 使用当前用户的 DPAPI 保护；Cookie 由第三方组件按原格式在本机保存，应作为登录凭据保管。

原文、最初 OCR 文字和校对后的材料分别保留。校对后旧报告失效，需重新整理；已加入问答的内容保留。删除资料会删除相关整理与导出关联记录，已导出的问答继续保留。

AI 输出经结构校验，公司、岗位、轮次必须出现在材料中，每题必须给出真实分段编号与连续原文引文。校验失败保留上一份有效报告和全部材料。处理状态持久化；过期任务可重试，迟到结果不能覆盖更新的处理尝试。图片失败可重试或手动补充。

单篇最多 30 张图片，单图下载上限 8 MB、像素上限 2000 万。每段文字不超过 60000 字、整理材料总计不超过 90000 字，OCR 每张最多保存 30000 字。

验证范围见 [面经功能验证记录](validation-experiences-2026-10-19.md)。

# 列表浏览状态恢复

## 使用效果

投递列表、面试问答分类、代码手撕的全部列表及分类列表，会分别记住搜索、筛选、页码和浏览位置；投递列表还保留排序。打开详情后返回、通过侧栏切换模块再回来，以及在同一标签页刷新，均按原条件恢复。

各列表的「重置筛选」会恢复默认条件、第 1 页和页面顶部。单独更改搜索、筛选或排序也会回到第 1 页。问答切换分类会清理批量勾选、批量操作弹窗和导入预览，浏览条件则按分类分别保存。

手撕题详情保留进入时的列表路径，从「全部题目」进入后仍返回全部列表；新题目第一次自动保存、更换详情地址时也保留来源。

## 保存与恢复规则

1. 地址中明确提供的列表条件优先；没有任何已知条件时，读取该路径上次的会话记忆；没有记忆时使用默认条件。
2. 地址用 `q` 表示搜索，`page` 表示页码，其他参数按列表能力声明。多选标签、状态使用重复参数，保留中文与特殊字符。
3. 默认状态也保留 `page=1`，明确表示用户已经清空条件，避免返回时恢复旧搜索。连续输入用路由替换更新当前历史项，不为每个字符新增历史记录。
4. 页面内打开详情或新建前，会先完成当前列表地址的更新，保留最后一次输入。浏览器前进、后退时按目标地址恢复。
5. 数据加载完成后再校正页码及恢复布局中实际滚动容器 `.main` 的位置。数据减少导致页码超出范围时，回到当前最后一页；零条结果对应第 1 页。
6. 更改条件时回到顶部；同一列表的不同查询分别保存位置，返回时等待列表渲染就绪再恢复。鼠标滚轮或触屏滚动可以中断尚未完成的位置恢复。

## 前后端职责

当前功能全部在前端完成，无新增接口、依赖和数据库字段。

- Pinia 管理应用内的视图记忆，sessionStorage 保留同一标签页会话中的记忆。刷新后可读取；跨设备同步不属于当前实现。
- 记忆按路径隔离，因此不同模块、不同分类、手撕题的全部列表互不覆盖。每个查询单独记录滚动位置。
- 只序列化声明过的视图字段。投递、题目、代码、登录凭据及未提交表单继续由原有流程管理，不复制到本缓存。
- 当前使用显式状态恢复，没有引入 KeepAlive。业务数据继续通过既有 API 和业务 store 加载、更新，视图恢复不替代数据加载。

会话记忆键为 `personal-app.page-views.v1`，最多保留 80 个列表路径、每个路径最近 8 个查询的位置。浏览器禁用存储、缓存损坏或写入配额不足时，降级为当前应用内的记忆，不阻断搜索和导航。URL 中的无效枚举或页码会按字段规则恢复默认值。

会话存储以浏览器来源和标签页隔离。`localhost` 与 `127.0.0.1`、不同端口或其他设备之间不共享记忆；本轮不承诺关闭标签页后仍能恢复。

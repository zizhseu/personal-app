# 主要岗位与展示编号验证（2026-11-02）

## 需求与改动边界

用户指出两个不同岗位均显示「第 2 次流程」，要求增加主要岗位选择，使投递列表使用所选岗位的状态、轮次等信息，并明确列表不需要「共 X 个轮次」。

原因是原页面直接显示内部 `position_version`，而同代次更正过岗位名称后可能存在多个分组。此次保留原分组和代次，单独生成唯一的 `displayOrder`，显示「岗位记录 N」。不合并真实岗位、不回填原始快照。该序号是当前分组的展示序号，切换主要岗位不改变它，删除或更正分组后则可能重排。

`application` 新增可空的 `primary_position`、`primary_position_version`，启动时幂等补列。未选择时默认当前岗位；选择只更新两列偏好，不修改当前岗位、状态、原更新时间、轮次或历史。列表和看板按所选成员生成视图，编辑弹窗仍读原始投递；历史主要岗位的状态和 Offer 决定只读。

- 在该备份副本连续运行两次迁移，然后为用户截图对应的多岗位记录选择另一组同代次岗位。展示序号为 1、2、3；摘要的状态、结果、最新轮次和成员 ID 符合该组实际记录，当前岗位与当前状态保持不变。
- 副本选择前后比较 `application`、`interview_round`、`status_history`、`round_result_history` 的全部原列，逐字段完全一致；只有新增偏好字段改变。外键检查无错误。
- 正式库只执行只读查询，确认新两列已加载，显式偏好仍为零；未替用户操作正式记录的主要岗位选择。备份中已有的 100 条投递、118 条轮次、155 条状态、107 条结果历史均未缺失、所有原字段未变。

## 独立页面实测

示例包含一次旧岗位和同代次的两个不同名称岗位。桌面实际宽度 1920 像素，手机使用 390 × 844 视口模拟，使用 DOM 与接口核验，未调用截图。

1. 三组分别显示唯一「岗位记录 1 / 2 / 3」，默认主要岗位为当前研究岗位。
2. 点击另一同代次岗位的「设为主要」，该组标注主要并排在最前；刷新后选择保持，序号不变，详情顶部的当前研究岗位与复筛状态保留。
3. 列表同步显示所选 Coding 岗位、面试、一面、已完成、11-04 10:00；不显示轮次总数。编辑该行时弹窗仍为原研究岗位和复筛状态，取消后不写入。
4. 390 像素下两个操作按钮均在组内、可用。点击研究岗位「设为主要」后通过真实返回入口回列表，显示研究岗位、复筛、测评、未开始、11-05 14:00，仍无轮次数量。
5. 1920 与 390 像素下页面宽度等于视口宽度，无页面横向溢出；窄屏表格保留自身横向滚动。最终页面控制台无错误或警告。

## 证据限制

这次验证不恢复旧版本从未保存的岗位或 Offer 决定。历史状态按已存阶段、结果所属状态、最新轮次类型依序取得，没有依据时标为未记录。主要岗位选择与当前业务流程分开，不提供从列表修改任意历史阶段状态的能力；历史轮次仍可按原轮次编辑结果和复盘。

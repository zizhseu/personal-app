## 页面实测

| 场景 | 结果 |
| --- | --- |
| 银行搜索后翻到第 2 页，打开详情再返回 | 搜索词、页码和滚动位置保持 |
| 投递列表设置状态、结果筛选及公司升序，切到设置后返回 | 查询条件与第 2 页保持，表头升序指示一致 |
| 问答分类 A 设置搜索、掌握状态、包含及排除标签、第 2 页，再打开详情返回 | 条件保持；将详情区域滚回顶部后，返回列表仍恢复原 120 像素位置 |
| 问答分类 A / B 设置不同条件后往返 | 各自恢复；A 的批量勾选从 1 条清为 0 条，不带到 B |
| 浏览器后退、前进 | 分别恢复 A / B 的查询与页码，A 的位置保持 |
| 问答第 3 页、100 像素位置刷新 | 接口延迟下仍保留搜索、状态、第 3 页及 100 像素位置 |
| 手撕全部列表带筛选、第 2 页进入详情，随后返回 | 返回 `/coding`，保持筛选和 80 像素位置，没有改为分类页 |
| 手撕全部列表与两个分类往返 | 三个列表的查询与页码分别保持 |
| 从手撕全部列表新建，首次自动保存后返回 | 仍返回全部列表并保留原条件，首次保存后的地址保留来源 |
| 手撕分类第 3 页有 5 条，独立库删除 5 条示例后刷新 | 加载完成后页码由 3 校正为 2，显示 10 条，没有留在空白页 |
| 输入搜索后在同一次验证操作中立即点击详情 | 返回仍保留最后输入，并回到匹配结果第 1 页 |
| 清空搜索、切模块再返回 | 搜索保持为空，地址保留 `page=1`，没有恢复旧词 |
| 三个列表点击「重置筛选」 | 搜索、过滤条件和页码恢复默认，地址均为 `?page=1` |

桌面验证视口为 1920 × 720，最终浏览器控制台没有错误或警告。另在 390 × 844 手机视口检查三个列表，文档与主内容区的横向溢出均为 0；检查后已清除手机模拟。本轮实测针对这些列表，未将 AI 面试输入草稿、设置表单等其他页面标记为已支持状态恢复。

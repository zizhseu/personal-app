# 旧版单岗位错误拆分的纠正与验证（2026-11-02）

## 根因与责任

旧版只在投递主记录保存岗位名，历史轮次、状态和结果没有岗位快照。后续迁移将快照保留为 NULL，这本身不等于用户投过第二个岗位。此前 UI 和服务端按「代次 + 名称」机械分组，导致当前岗位成为空组，原流程被放入「岗位未记录」。当前结果选择也采用了错误的排除规则。

此前测试确有空快照场景，但把错误的两组预期当成正确，并未使用真实旧库形状检验业务含义。138 项回归通过不是替代真实数据验证的理由；本次将原错误预期纠正，并补齐下面的证据。

## 当前归属规则

同次流程先收集已知名称；若只有一个名称，空快照归到同一岗位展示，不生成虚假的第二岗位，也不持久化推导名称。整次流程名称都未知，或同代次多名称且缺乏明确关联时仍保留未知。不同代次不互相借用名称，同名再次投递仍分开。

前端分组与当前结果使用同一个解释器；服务端分组、轮次归属、阶段复用、补录和删除使用对应解释器。删除还必须携带用户确认的三类成员 ID；成员变化、旧空组或旧客户端请求返回 409，事务不执行。
